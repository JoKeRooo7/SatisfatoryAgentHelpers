# Интерфейсы управления специалистами

Статус: проектное предложение по PLAN-030, 2026-11-09. Интерфейсы ещё не реализованы. Решения опираются на [исходный запрос](../../first_prompt); механика задач — в [tasks_and_plans.md](../logic/tasks_and_plans.md), сетевая осуществимость — в [compatibility.md](compatibility.md).

## Границы экранов

| Поверхность | Основная обязанность | Когда доступна |
| --- | --- | --- |
| Отдельное окно ОС «Satisfactory Agent Helpers» | Базовые настройки, доступность, производительность, параметры управления | На локальном клиенте с модом, после запуска игры; состояние мира показано явно |
| Пульт с посадочной площадкой | Найм и состояние доставки специалистов, общие правила базы | В загруженном мире у действующего пульта |
| Взаимодействие с ботом | Текущая задача, состояние, инвентарь, привязанные склады и команды конкретному боту | При обычном взаимодействии с живым доступным ботом |
| Предмет-планшет | Задачи, карта ботов и коммуникаций, планы, уведомления | У игрока с модом и доступом к своей системе специалистов |
| Инструмент привязки | Выбор складов и назначение специалистов без физической транспортной линии | В режиме привязки планшета/инструмента |

Окна не хранят отдельную копию симуляции. Открытый планшет показывает снимки и изменения authority. Закрытие интерфейса не прекращает работу ботов. На dedicated server графические окна не создаются; серверные правила читаются из версионированной конфигурации. Клиент без мода не получает эти экраны автоматически.

## Отдельное окно настроек

Основной технический кандидат — нативное Slate `SWindow` внутри процесса игры: самостоятельное окно ОС, без HTTP, локального сервера и отдельного Python runtime. Epic описывает SWindow как верхнеуровневое окно; это подтверждает наличие механизма в UE, но не его работоспособность в конкретной packaged сборке Satisfactory. Ранний эксперимент проверяет доступность Slate-модулей и создание/уничтожение окна в совместимом SDK.

Обязательные проверки эксперимента: открытие после загрузки главного меню и мира; повторное открытие; Alt-Tab; полноэкранный и оконный режим; изменение DPI; второй монитор; возврат мыши/клавиатуры игре; выход в главное меню; завершение процесса; отсутствие захвата горячих клавиш текстовыми полями. Сбой окна не останавливает симуляцию. В меню мода остаётся доступ к тем же настройкам. Если технически требуется отдельный процесс, это отдельное решение владельца: IPC, упаковка, поддержка платформ и права на ассеты пересматриваются до реализации.

Предлагаемый порядок запуска: при первом старте окно открывается после готовности главного меню; пользователь может отключить последующее автоматическое открытие. Переход в игровой мир не создаёт второе окно. Закрытие крестиком сохраняет подтверждённые настройки и закрывает только панель. Положение сохраняется в пределах доступных мониторов; при исчезнувшем мониторе окно возвращается в видимую область.

| Раздел | Примеры параметров | Область действия |
| --- | --- | --- |
| Интерфейс | Масштаб текста, размер значков, контраст, схема цветов, язык, компактные карточки | Личный профиль клиента |
| Управление | Открыть планшет, открыть окно, режим привязки, жесты карты; проверка конфликтов клавиш | Личный профиль клиента |
| Карта | Включённые слои, высота среза, частота обновления, подробность маршрутов | Личный профиль клиента |
| Уведомления | Звук, степень важности, агрегация, значки над ботами | Личный профиль клиента |
| Качество | Детализация ботов и капсулы, расстояние отображения значков, анимация меню | Личный профиль клиента |
| Правила базы | Лимит специалистов, разрешённые зоны, разрешение строительства/сноса, сбор в простое | Authority мира; изменение только уполномоченным игроком |
| Нагрузка | Бюджеты планирования и анализа, частота фонового наблюдения | Authority мира; разумные диапазоны после измерений |

Схема настроек общая с внутриигровым меню, а не два расходящихся файла. Кнопки: «Применить», «Отменить изменения», «Сбросить раздел». Локальное изменение применяется сразу, если это поддерживается; необходимость перезапуска указана рядом с параметром. Серверное изменение имеет состояния «Отправлено», «Применено» или конкретную причину отказа. Сброс локального интерфейса не сбрасывает мир, специалистов и их склады. Сброс правил мира требует отдельного подтверждения с перечнем влияния.

SML предоставляет конфигурационные схемы и доступ к настройкам через меню мода и JSON. Для проекта это кандидат механизма хранения; конкретное API проверяется по выбранному SDK. Пользователь не обязан редактировать JSON. Повреждённый профиль восстанавливается с сообщением, а диагностическая копия сохраняется локально без отправки куда-либо.

## Пульт, найм и капсула

Пульт открывается стандартным действием взаимодействия. Вверху — база, число живых специалистов, состояние площадки, доступные ресурсы. Основная вкладка «Нанять»: портрет/скин из доступных игровых ассетов, имя, роль, возможности и точная цена. Для цены показываются «в наличии / требуется» и выбранный источник оплаты. Скины и роли генерируются заранее, предложение имеет постоянный ID; таймер обновления идёт по игровому времени authority. Остановка игры и закрытое меню не создают несколько обновлений подряд.

| Состояние найма | Что видит игрок | Допустимое действие |
| --- | --- | --- |
| Доступен | Цена, источник оплаты, ожидаемая роль | «Нанять» |
| Не хватает ресурсов | Недостающие предметы и количества | Сменить разрешённый склад оплаты; вернуться позже |
| Проверка найма | Краткий индикатор и заблокированная повторная отправка | Закрыть окно; статус остаётся в планшете |
| Доставка | Очередь, занятая площадка, выбранный безопасный слот | Наблюдать; отмена только по правилам транзакции найма |
| Прибыл | Бот вышел из капсулы, доступна карточка | Выбрать склад и приоритеты |
| Препятствие/пульт удалён | Причина переноса или остановки доставки | Устранить препятствие, выбрать новую площадку либо оформить разрешённый возврат |

Оплата, появление бота и возврат определяются серверной транзакцией, анимация капсулы их не подтверждает. Повторный клик/переподключение не оплачивает один наём дважды. Предложение с начатым наймом не исчезает при обновлении списка. Если меню обновилось между просмотром цены и отправкой команды, игрок получает актуальную цену до нового подтверждения. UI никогда молча не подменяет роль или цену.

Посадочная зона в мире показывает границы и причину блокировки; капсула не приземляется поверх игрока, контейнера или уже строящегося объекта. Анимация запускается только после подтверждённого состояния доставки. Отсутствующий эффект не мешает получить уже созданного бота. Вопрос использования игрового меша капсулы и готовых анимаций остаётся до проверки ассетов.

## Карточка специалиста

Один экран для взаимодействия в мире и выбора бота из планшета: имя и роль; здоровье/опасность; рюкзак; назначенные склады; текущая задача; следующая допустимая задача; потребности; история последних причин перехода. В шапке всегда видны причина ожидания и конкретное действие, которое может её устранить.

Команды разделены по назначению: «Пауза», «Продолжить», «Вернуться», «Выбрать склад», «Перенести ресурсы», «Приоритеты», «Показать маршрут». Отмена относится к конкретной задаче и показывает, что уже перенесено или построено. «Вернуться» не телепортирует бота и не очищает его рюкзак. Настройки собирателя показывают только допустимые собираемые ресурсы; отсутствующий в текущей версии предмет не выбирается. Специалист не получает несуществующие способности из-за элемента меню.

Состояния смерти: живая карточка заменяется архивной записью с причиной, временем мира, местом и содержимым подтверждённого ящика. Кнопки приказов отключены; есть «Показать ящик» и задача переноса оставшихся работ. Нанятый на замену бот получает новую идентичность. История погибшего не переписывается.

## Планшет

Предлагается пять основных разделов: «Специалисты», «Задачи», «Карта», «Планы», «Уведомления». Последний открытый раздел и фильтры сохраняются в личном профиле. Поиск по имени/номеру и фильтр по базе доступны без перехода в настройки.

| Раздел | Главная информация | Переход из записи |
| --- | --- | --- |
| Специалисты | Роль, текущая работа, потребность, здоровье, склад | Карточка бота или его положение на карте |
| Задачи | Исполнитель, приоритет, зависимость, состояние, причина ожидания, прогресс | Бот, участок карты, родительский план |
| Карта | Боты, пути, ресурсы, коммуникации, опасности, ограничения, изменения | Карточка объекта/ребра/узла |
| Планы | Ревизия, стоимость, исполнители, эффект, ожидание решения, выполненная доля | Просмотр и правка подграфа |
| Уведомления | Сгруппированные потребности, готовые планы, смерти, заблокированные работы | Конкретная задача/бот/план |

У каждой задачи отображаются фактические данные: создана, назначена, идёт к цели, выполняет действие, ожидает условие, завершена, отменена или требует перепланирования. Словарь отображаемых названий связывается с каноническими состояниями task-контракта; интерфейс не вводит второй автомат. «Прогресс» показывается только при известной измеримой работе: перенесено X/Y, построено X/Y, обследовано X/Y. Для неизвестного объёма — название стадии вместо выдуманного процента. Очередь допускает сворачивание служебных шагов; раскрытие показывает источники и причины.

### Ранний сценарий M1: перенести ресурсы

В разделе «Задачи» планшета доступна кнопка «Перенести ресурсы». Та же форма открывается из карточки переносчика, где выбранный бот уже указан исполнителем. Это внутриигровая команда первого сценария между двумя складами; привязка домашнего склада сама по себе не создаёт доставку.

Форма содержит явно выбранные источник, приёмник, предмет и положительное количество. Источник и приёмник выбираются из поддержанных контейнеров или выделением объекта в мире; подписи и положение позволяют проверить выбор. Скрытого склада, неявного забора из инвентаря игрока и автоматической подстановки ближайшего назначения нет. Один контейнер нельзя выбрать обеими сторонами. Предмет выбирается из наблюдаемого содержимого источника; рядом показываются доступное количество, вместимость назначения и время снимка.

Перед подтверждением сводка показывает исполнителя, обе точки, предмет, заказанное количество и известную допустимость: права, поддержка контейнеров, доступность ресурса/места, состояние маршрута. Неизвестное или недоступное отмечается конкретной причиной. Предварительный просмотр не резервирует предметы и не обещает неизменность мира. Кнопка «Создать доставку» отправляет намерение authority, который повторно проверяет конкурентно меняющиеся условия; подтверждённая задача появляется со стабильным `TaskId`, либо форма показывает причину отказа. Повтор отправки одной команды не создаёт вторую доставку.

После создания открывается карточка задачи: `TaskId`, исполнитель, источник/приёмник, перенесено и осталось, текущий шаг, маршрут или причина его отсутствия, причина ожидания и допустимое следующее действие. Частичная передача учитывает фактически доставленное; остаток и груз в рюкзаке видны отдельно. Исчезновение контейнера или заполнение приёмника не меняет выбранное место молча: задача показывает блокировку и действие явного выбора нового назначения. Отмена использует общие правила безопасной границы и сохраняет физически перенесённый груз.

## Карта и переключение режимов

Карта имеет единые координаты мира, выбор высоты/этажа и три режима: «Факт», «План», «Перестройка». Слои фильтруются независимо: передвижение ботов, склады, конвейеры, трубы, электричество, дороги/маршруты транспорта, железная дорога и прочие поддержанные адаптерами коммуникации. Внутри конвейерного слоя все конвейеры относятся к одному типу; скорость/уровень остаётся свойством ребра. Внешний вид слоя не объединяет физически несвязанные сети.

| Режим | Представление | Редактирование |
| --- | --- | --- |
| Факт | Подтверждённые объекты, текущие маршруты и степень свежести данных | Выбор, инспекция, постановка ограничения |
| План | Предлагаемые связи и объекты поверх факта, цели и исполнители | Ключевые точки, запреты, обязательные связи, отправка аналитику |
| Перестройка | Удаляемое — красное с перечёркиванием; добавляемое — светлосерое с пунктиром; сохраняемое — обычный контур | Выбор допустимого подграфа работ и просмотр порядка |

Форма и подпись дублируют цвет. Фон/контур светлосерых объектов проверяются на читаемость; в контрастной теме допускается усиленный тёмный контур. На пересечениях видны направление и высота, а совпадающие линии разводятся или выбираются через список. Толщина ребра не притворяется пропускной способностью без легенды. Маршрут бота отличается от конвейера рисунком линии и пиктограммой.

Участки «ещё не проанализирован», «анализируется», «готов», «устарел», «недоступен» имеют разные подписи/паттерны. Изменение участка во время работы аналитика не делает весь мир автоматически готовым. Для недоступного/выгруженного объекта показываются время снимка и отсутствие текущего подтверждения. Подсветка означает статус данных, а не разрешение строить.

Панорамирование, масштаб, выбор, снятие выбора и переход к объекту работают мышью и клавиатурой; горячие клавиши переназначаются. Меню не перехватывает игровое движение, когда не имеет фокуса. На очень плотной карте применяется масштабное объединение, ограничение подписей и выбор объектов из раскрываемого списка; все подробности не рендерятся одновременно.

## Правки графа и принятие работ

Пользователь выбирает узел, ребро или область, затем задаёт одно действие: «Сохранить здесь», «Запретить изменение», «Обязательная точка», «Обязательная связь», «Не проводить через область». Ограничение видно на карте и в списке с автором. Черновая правка меняет проектное ограничение; она не перемещает реальную конструкцию. Можно отменять собственные черновые правки до отправки.

После отправки аналитик получает одну задачу с новой версией ограничений. План показывает авторство и основание: версия снимка, версия ограничений, время расчёта и какая часть уже построена. До готового перерасчёта прежняя рекомендация помечена устаревшей; выполненные объекты остаются фактом. Невозможные ограничения дают конкретный конфликт, например «обязательная точка находится в запрещённой зоне», с выбором соответствующих элементов.

Принятие всего плана или подграфа сначала показывает точный состав работ, материалы, затрагиваемые объекты, исполнителей и обязательные зависимости. Если выбранный участок зависит от другого, UI предлагает включить зависимость или уменьшить выбор; скрыто принимать внешние работы нельзя. Отдельно подтверждается демонтаж по утверждённому перечню. Уже выполненный шаг не выдаётся за повторно оплачиваемое строительство. Изменившаяся ревизия, стоимость или состав демонтажа требует нового просмотра до подтверждения.

Перед исполнением authority проверяет актуальность и разрешения. Для устаревшей рекомендации кнопка «Принять» недоступна с действием «Обновить план». Отправка на доработку сохраняет предыдущую ревизию и выбранные ограничения. Частичное исполнение видно как фактическая выполненная часть, очередь работ и зона нового анализа, а не как исчезнувший план.

## Привязка складов

Связь логическая: физический конвейер, кабель, коллизия или невидимый транспорт в мире не создаются. Инструмент использует привычные стадии выбора конечных точек, подсветку цели и краткую сводку. В обычном режиме его линии невидимы; в режиме привязки и на соответствующем слое карты они доступны для проверки.

Сценарий: выбрать контейнер → выбрать конкретных ботов или явно указанную группу роли → задать режим доступа «складывать», «забирать» или оба → проверить фильтры ресурсов и приоритет → подтвердить. Привязка к группе роли означает правило для текущих и будущих ботов выбранной базы только после явного выбора этого режима. Простое выделение нескольких ботов не создаёт такого наследования. Один контейнер может иметь много назначений, бот — несколько контейнеров с разными приоритетами.

Снятие связи доступно из контейнера и карточки бота. Операция в пути получает новую задачу выбора назначения; уже изъятые ресурсы остаются в реальном рюкзаке. Удаление/замена/перемещение склада помечает связь недействительной, не переназначает её случайному объекту по координатам. Недоступный или неподдерживаемый контейнер нельзя подтвердить. Одинаковые назначения нормализуются, противоположные правила разрешаются явным приоритетом и фильтром. Личный контейнер бота не считается отдельным виртуальным бесконечным инвентарём.

## Значки и уведомления

Потребность содержит предмет, количество, срочность и ID запроса. Над ботом показывается сгруппированный бейдж, а не новый виджет на каждый тик или на каждую попытку запроса. Один запрос сохраняет идентичность при делегировании; доставка обновляет остаток. Для нескольких ресурсов — стабильный ряд и индикатор «ещё N» с раскрытием в карточке.

Размещение выполняется в экранных координатах: ближайшие пересекающиеся бейджи получают разные полосы и короткие линии к ботам. При недостатке места группа сворачивается в один кластер, который раскрывается по выбору. Поэтому требование отсутствия наложений выполняется ограничением видимого содержания, а не бесконечным раздвиганием текста за край экрана. Выбранный бот и критическая опасность имеют приоритет. За экраном — компактный указатель; за препятствием обычные бейджи скрываются, выбранный доступен по отдельной настройке. Размер, дальность, число видимых групп и отключение мировых бейджей настраиваются.

Уведомления планшета объединяются по причине/боту/плану. Повтор одного дефицита обновляет существующую запись. Прочтение не отменяет потребность. Системная ошибка, отсутствие ресурсов и смерть имеют разные категории; непрерывные звуковые повторы запрещены. Клик ведёт к месту решения. Готовый анализ создаёт уведомление о конкретной ревизии, а не одинаковые записи для каждого затронутого ребра.

## Удаление объектов и потеря связи

Если пульт/площадка удалены другим игроком, открытое меню показывает это событие и прекращает отправлять команды в мёртвый объект. Доступ к уже нанятым специалистам и истории остаётся через планшет. Доставка получает состояние authority согласно [persistence.md](persistence.md), а UI не восстанавливает платформу автоматически. При потере соединения данные становятся доступными для просмотра с меткой времени; новые команды отключены до восстановления и получения актуальных ревизий. Повтор неподтверждённой команды сверяется по ID.

Табличка с инструкцией установки для клиента без мода возможна только как настоящий поддержанный ванильный объект и только после успешной сетевой проверки. Новый модовый экран на таком клиенте не обещается. Аналогично отображение сканера вместо планшета и колонны вместо платформы — отдельные гипотезы совместимости, не поведение UI по умолчанию.

## Приёмка и источники

До реализации: согласовать карту экранов, действия над планом и формулировки. В игре: проверить обычный и увеличенный текст, 1080p/1440p/4K, DPI/мониторы, мышь/клавиатуру/поддерживаемый игрой контроллер, фокус окон, пустую и заполненную базу, устаревшие данные, сотни уведомлений, удаление объектов и переподключение. Конкретные нагрузки согласуются с [performance.md](performance.md); перечисление разрешений экрана не является заявлением о прошедшей проверке.
