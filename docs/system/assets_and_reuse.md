# Игровой стиль, ассеты и переиспользование

Статус: исследование и визуальная спецификация по PLAN-030, 2026-11-09. Сторонние исходники, игровые модели, шрифты, текстуры и звуки в эту ветку не скопированы. Ни один визуальный ассет ещё не проверен в установленной игре. Реестр ниже фиксирует кандидатов и ограничения; он не подтверждает универсальное право на коммерческую перепаковку материалов.

## Решение по источникам

Пользователь задаёт визуальное направление самой Satisfactory и просит существующие игровые скины/объекты. Поэтому первый выбор — штатные механизмы UE/SML и ссылки на контент установленной игры, а не декоративный набор из стороннего каталога. Общие алгоритмы реализуются самостоятельно там, где штатный механизм не покрывает предметную задачу; собственный UI собирается вокруг доступных игровых компонентов. Непроверенные модели роботов, анимированные NPC-паки и новые шрифты в план не включаются.

Документация SML описывает переиспользование базовых ассетов через placeholders с теми же именами/типами/путями: при упаковке они не включаются в мод, а во время игры ссылка разрешается в контент базовой игры. Это механизм ссылки, а не извлечение и повторная поставка материалов. Конкретный путь и тип каждого выбранного объекта требуется проверить в совместимом Starter Project; похожее имя файла не считается доказательством.

Перед добавлением зависимости/файла эта запись расширяется: точная версия и commit, автор, исходный URL, список реально используемых файлов, полный текст относящейся лицензии и уведомлений, способ поставки, выполненные изменения, обязательства и результат проверки. Кандидаты с неизвестными условиями остаются вне поставки. Собственные документы этой ветки не выдают этим материалам новую лицензию.

Документация SML отдельно предупреждает о защищённости извлечённых ассетов Coffee Stain и необходимости разрешения на их распространение. Экспорт игровых шрифтов/картинок в отдельное desktop-приложение не является частью базового решения. Если отдельный процесс понадобится, визуал должен использовать собственные разрешённые элементы либо отдельно согласованные материалы. Этот выбор нельзя прятать за формулировкой «как в игре».

## Визуальное направление

Спецификация ниже — предложение, а не результат измерения оригинальных окон игры. После доступа к установленной версии дизайнер снимает референсы прямо из игры: меню машины, инвентарь, окно строительства, ресурсный сканер, карту, костюм игрока, таблички и подходящую капсулу. Для каждого референса сохраняются источник/версия, ракурс или таймкод, наблюдение и применённое решение. До этого нельзя утверждать точное совпадение шрифта, палитры, пропорций и движения.

| Часть | Предлагаемое направление | Проверяемый критерий |
| --- | --- | --- |
| Оболочка | Сдержанные тёмные панели, технические разделители, акцент действия в существующем игровом стиле | Рядом с штатным окном мода не возникает иной визуальной системы; основной текст читается при обычном размере |
| Типографика | Существующий UI-шрифт игры и его доступные начертания; выравнивание чисел | Кириллица, длинные роли, цифры, большие цены и увеличенный масштаб не обрезаются |
| Ресурсы | Оригинальные игровые иконки, количества текстом и подписью по фокусу | Предмет узнаваем без новой пиктограммы; количество не сливается с изображением |
| Планшет | Утилитарное оборудование мира игры; предмет и интерфейс функционально связаны | Руки не проходят сквозь модель, виден инструмент, взаимодействие не ломает стандартный ввод |
| Специалист | Тот же человеческий масштаб и скелет, что у игрока; роль обозначена бейджем/доступной окраской | Узнаваемая модель игрока; нет обещания несуществующего официального скина или нового оборудования |
| Пульт/площадка | Компактный промышленный объект из доступных игровых деталей | Достаточный проход к пульту, зона выхода из капсулы и границы занимаемого места согласованы с коллизиями |
| Карта | Тип связи обозначен рисунком/значком/подписью, план поверх подтверждённого факта | Граф читается на плотном участке и при нарушении цветоразличения |
| Перестройка | Красный демонтаж, светлосерое добавление, разные штрихи и текст | Выбранный пользовательский цвет сохраняется в обычной теме; доступность обеспечена дополнительным кодированием |
| Движение | Короткая функциональная анимация, доступное снижение эффектов | Меню не задерживает команды ожиданием анимации; действия не маскируют фактический отказ |

Фиксированные HEX-цвета и пиксельные размеры до исследования реальных окон не назначаются как «официальные». Стилевые токены берутся из доступных игровых компонентов либо фиксируются после сравнения. Ограничение на читаемость важнее декоративного сходства, но изменение общего направления обсуждается с владельцем.

## Модели, анимации и физическое присутствие

Игровой меш в новом классе остаётся новым модовым объектом. Повторное использование модели игрока не делает бота настоящим подключённым игроком, а стандартный сканер в руке не заставляет vanilla-клиент понимать планшет. Внешний вид, поведение, сохранение и репликация проверяются независимо.

Для бота проверяются фронт/профиль/спина/вид сверху, ходьба по лестницам и склонам, повороты с рюкзаком, перенос, сбор, использование инструмента, бой, лечение и смерть. Для NPC нельзя автоматически считать пригодными все анимации player pawn. Отсутствующее движение сначала решается доступной штатной анимацией или собственным разрешённым материалом; случайное телепортирование предметов не выдаётся за завершённую визуальную интеграцию.

Для капсулы требуются фазы подлёта, замедления, контакта, открытия, выхода и отлёта. Проверяются высота объекта, коллизия, нахождение игрока на площадке, низкие потолки, недоступный выход, разрушение площадки и загрузка сохранения посреди доставки. Косметическая анимация не владеет жизненным циклом найма. При ограничении эффектов можно уменьшать дым/звук/детализацию, сохраняя факт прибытия и понятный статус.

Для графики сначала проверяются существующие LOD, culling, анимационные настройки и подходящие механизмы движка. Новая геометрия и сложная физика только для нужного видимого поведения. Нельзя обещать нулевой расход памяти от ссылок на игровые ресурсы: загрузка мешей, анимаций, шрифтов и виджетов всё равно имеет runtime-стоимость. Дальние боты могут иметь меньшую визуальную частоту, но реальные действия/коллизии не подменяются фиктивной добычей.

## Проверка прав и качества до поставки

Технический художник проверяет фактический состав упаковки: собственные файлы, разрешённые зависимости, отсутствие случайно включённых извлечённых игровых материалов и доступность всех ссылок в чистой целевой установке. Reviewer сверяет версии/лицензии и реестр, а визуальный reviewer сравнивает UI/объекты с сохранёнными референсами. Проверяется режим без отдельного окна и на dedicated server, где Slate/UI-контент не должен создавать графическую зависимость.

До первой играбельной поставки нужны asset manifest, разрешённые референсы, проверка коллизий/движений/кириллицы/контраста, стоимость загрузки и кадра, а также проверка работы при отсутствующем кандидате или обновлённом пути. В текущей ветке эти проверки запланированы, но не выполнены.

## Primary sources

Дата просмотра: 2026-11-09. Документация `latest` меняется; перед реализацией источники и фактический SDK сверяются заново.

- [Reusing Base Game Files](https://docs.ficsit.app/satisfactory-modding/latest/Development/ReuseGameFiles.html) — штатный способ runtime-ссылок без переноса игровых файлов в мод.
- [Extracting Game Files](https://docs.ficsit.app/satisfactory-modding/v3.11.3/Development/ExtractGameFiles.html) — отличие просмотра/извлечения от разрешённого распространения.
- [Machine Interaction GUI](https://docs.ficsit.app/satisfactory-modding/v3.11.3/Development/BeginnersGuide/SimpleMod/machines/SimpleInteraction.html) — пример взаимодействия и стилизации через игровые виджеты.
- [Widget Blueprint Hooks](https://docs.ficsit.app/satisfactory-modding/latest/Development/ModLoader/WidgetBlueprintHooks.html) — встраивание дополнительного UI без полной замены исходного окна.
- [SML / Starter Project source](https://github.com/satisfactorymodding/SatisfactoryModLoader) — кандидат SDK/примеров; полный лицензионный анализ конкретной поставки остаётся отдельной задачей.
- [Epic: SWindow](https://dev.epicgames.com/documentation/en-us/unreal-engine/API/Runtime/SlateCore/SWindow) — кандидат отдельного окна; наличие API не доказывает совместимость конкретной сборки игры.
