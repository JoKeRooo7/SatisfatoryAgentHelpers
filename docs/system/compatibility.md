# Совместимость с игрой и другими игроками

Проверено по открытой документации 2026-11-09. Реальные игровые подключения, packaged builds и версии установленной игры ещё не проверены. Ни один режим ниже не объявляется уже работающим.

## Что установлено источниками

1. SML различает моды, требуемые на удалённой стороне, через `RequiredOnRemote` и диапазон `RemoteVersionRange`. По умолчанию мод требуется на обеих сторонах. Это проверка списка/версий, а не механизм доставки ассетов или замены классов. Источник: [Releasing A Mod, Special Fields](https://docs.ficsit.app/satisfactory-modding/latest/Development/BeginnersGuide/ReleaseMod.html).
2. В исторической заметке перехода SML 3.7 → 3.8 отмечено: SML-клиент может входить на vanilla-сервер, обратное подключение vanilla-клиента к SML-серверу тогда не поддерживалось. Это не доказательство неизменности ограничения в новой установленной версии. Источник: [Upgrading from SML 3.7.0 to 3.8.x](https://docs.ficsit.app/satisfactory-modding/latest/Development/UpdatingFromSml37.html).
3. Документация требует проверять multiplayer на практике при собственном вводе и изменении состояния мира. Источник: [Multiplayer](https://docs.ficsit.app/satisfactory-modding/latest/Development/Satisfactory/Multiplayer.html).

Актуальный handshake исходного кода SML не был независимо подтверждён в этой работе: GitHub connector для публичного дерева исходников вернул `Transport closed`, а поиск не предоставил достаточного текущего кода. Следовательно, нельзя честно превратить историческое ограничение в уверенное утверждение о всех версиях SML.

## Три разных клиента

| Хост | Клиент | Проектный статус | Планируемый доступ | Что требуется доказать |
| --- | --- | --- | --- | --- |
| Игра + SML + полный мод | Игра + совместимые SML и полный мод | Основной целевой режим | Пульт, планшет, боты, кастомная платформа, капсула, планы | Корректность сетевых команд, репликации, JIP и сохранений |
| Игра + SML + мод | Игра + SML, без нашего мода | Отдельный исследовательский режим | Если эксперимент успешен — только базовые игровые представления и взаимодействия | Допуск соединения, отсутствие неизвестных классов/предметов/RCO, безопасные операции и длительная сессия |
| Игра + SML + мод | Полностью vanilla, SML отсутствует | Неподтверждённая цель с риском ограничения загрузчика | Не обещано; табличка возможна только после успешного входа в мир | Само подключение и совместимость сетевого протокола SML до графики |
| Vanilla-сервер без нашего мода | Клиент с нашим модом | Симуляция ботов недоступна | Локальные настройки/состояние «хост не поддерживает мод», если разрешает загрузчик | Отсутствие несанкционированных изменений чужого сервера |

На dedicated server нет локального окна и локального игрока. Полный мод должен иметь отдельные подтверждённые server build targets; поддержка хостовой игры не доказывает dedicated support. Console/cross-platform clients с недоступным SML не заявляются поддерживаемыми.

## Почему ванильный меш не решает сетевую совместимость

Сеть передаёт не только видимый меш. Важны класс Actor, компоненты, реплицируемые свойства, классы предметов/рецептов, ссылки на объекты, RCO и способ появления сущности. Если NPC создан экземпляром собственного модового класса, использование ванильного костюма не делает его ванильным сетевым объектом. Скрытие капсулы не удаляет неизвестный класс из сетевой сериализации.

Поэтому предложение «для клиента без мода показывать колонну с табличкой» исследуется как отдельное серверное представление, а не автоматический fallback движка. Возможный прототип строится только из реально существующих базовых классов с допустимой штатной конфигурацией и серверной логикой, которую не нужно реплицировать клиенту. Дополнительные косметические слои модифицированного клиента должны иметь те же footprint/коллизии, что базовое представление, иначе игроки будут видеть разные проходы и точки разборки.

Реализуемость управления ванильным персонажем как NPC, его движения, анимации, оружия, инвентаря и AI-controller без появления неизвестных сетевых ссылок не установлена. Если для этого требуется собственный pawn, смешанный режим не проходит gate. Требование бота с видом игрока остаётся целью полного режима.

## Боты и список игроков

Бот — игровая сущность с `BotId`, ролью и сгенерированным именем. Он не получает вымышленный Steam/Epic аккаунт и не изображает реальное подключившееся сетевое соединение. Сообщение вида `[bot][кладовщик] Имя` и запись в интерфейсе допускаются как UI-представление, если штатные каналы игры это поддерживают. Появление именно в ванильном player list требует отдельного эксперимента; его отсутствие не блокирует логику NPC.

## Переговоры режима и отказ

До выпуска выбирается один подтверждённый профиль. Для первого полного режима `RequiredOnRemote` остаётся обязательным; не понижать его до `false` ради обхода проверки. Если исследуется host-only профиль, необходимо отдельно проверить и допустимость отсутствия самого SML на клиенте. При неподдерживаемом режиме соединение должно завершаться контролируемым штатным отказом до создания модового контента, где это возможно средствами загрузчика. Если этого нельзя добиться, профиль не выпускается.

Если клиент уже вошёл в разрешённую смешанную сессию, он не получает модовые планшеты, инвентарные предметы и кастомные RPC. Сообщение об установке выводится ванильным знаком/текстом только после проверки возможности такого представления. Планшет нельзя автоматически «превратить в сканер»: это разные item descriptor и equipment semantics. Для mixed-профиля безопаснее вообще не передавать новый предмет неподдержанному клиенту.

## Разборка объекта чужим игроком

Общий авторитетный объект имеет один `StationId` и одно событие удаления независимо от косметического вида у наблюдателя. Если mixed-прототип использует колонну/знак как оболочку, разборка любого опорного элемента должна переводить станцию в `Unavailable` и отменять новые посадки; нельзя оставлять рабочий пульт без физического основания у второго игрока. Возврат материалов вычисляется единожды по общей спецификации и не даёт одновременно стоимость колонны и стоимость платформы.

Имеющиеся боты сохраняются, освобождают привязку к станции и выполняют безопасные разрешённые задачи с доступными складами. Непоявившиеся оплаченные боты переходят в возврат/переназначение по контракту найма. Если при разборке невозможно одновременно согласовать коллизии, refund и жизненный цикл, такой mixed-прототип не считается успешным.

## Порядок доказательства host-only

1. Зафиксировать game build, branch, SML release/tag, модовые версии и платформы обеих копий. Проверить vanilla→vanilla baseline.
2. Проверить admission: хост с одним SML, клиент без SML; затем хост SML+мод, клиент SML без мода. Это разные тесты, а не одна галочка «без мода».
3. В минимальной карте проверить только серверную логику без новых сетевых классов. Снять логи server/client и причины отказа.
4. По одному добавить базовую оболочку станции, NPC, инвентарь, урон, перенос, найм. На каждой ступени проверять JIP, уход/повторный вход и выгрузку области.
5. Проверить разборку станции и склада немодифицированным клиентом, смерть бота, сбор его ящика, save/reload и двухчасовую совместную сессию под согласованной нагрузкой.
6. После каждого изменения SDK повторить gates. Успех только подключения не доказывает безопасность игрового цикла.

Провал admission закрывает дальнейшее обещание vanilla-совместимости для этой связки. Он не исправляется заменой моделей. До получения доказательств первый играбельный релиз планируется для одиночной игры и полного модифицированного host-and-play.

## Совместимость со сторонними модами и обновлениями

Мод не меняет глобально все контейнеры/рецепты/врагов. Неизвестные объекты отображаются как неподдержанные и остаются read-only, пока нет проверенного адаптера. Проверяются типы и возможности, а не только имя класса. Конфликт горячих клавиш решается переназначением; конфликт слушателей lifecycle — корректным освобождением подписок; конфликт построек — повторной подготовкой места перед действием.

Перед разработкой фиксируется установленная связка игры, CSS Unreal Engine, Starter Project, SML и Alpakit. Нельзя брать произвольный свежий Unreal из Epic Launcher. [Обновление SML 3.11 → 3.12](https://docs.ficsit.app/satisfactory-modding/latest/Development/UpdatingFromSml311.html) описывает смену игрового/движкового окружения, но на момент чтения содержит предупреждение о невыпущенной поддержке. Страницы также показывают dev/outdated-предупреждения. Поэтому номер версии не выбирается только по слову `latest`: сверяются опубликованный release и установленная игра.
