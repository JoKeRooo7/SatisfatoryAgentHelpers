# Контракты компонентов

Статус: спецификация, а не реализованные типы SDK. Цель — единые границы для независимых исполнителей. Каждая операция с миром проходит авторитетную подготовку и завершает одну связанную обязанность.

## Идентичность и версии

| Значение | Семантика | Кто создаёт и проверяет |
| --- | --- | --- |
| SaveId | Устойчивое пространство ID конкретного сохранённого мира | Lifecycle при первом запуске |
| SessionGeneration | Новое поколение на каждой загрузке/смене мира | Lifecycle; отклоняет старые async-результаты |
| EntityId + Generation | Устойчивая сущность и поколение её существования | Registry; удаление создаёт tombstone |
| CommandId | ID пользовательской команды для идемпотентности | Клиент создаёт, authority связывает с игроком и результатом |
| TaskId / OperationId | Внутренняя задача и отдельный микрошаг | Scheduler / исполнитель плана |
| PlanId + Revision | Неизменяемая редакция решения | Plan service; отображаемый номер не служит ключом |
| GraphRevision / InventoryRevision | Версия снимка области/ресурсного состояния | Владелец области после изменения |
| LeaseId + ExpiresAt | Временное право исполнителя на ресурс/задачу | Reservation service по времени симуляции |

Сервер не принимает присланный клиентом PlayerId как доказательство полномочий: контекст игрока берётся из соединения. Имена и координаты используются для представления, а не как устойчивый ID склада. Нулевые/неверные обязательные поля отклоняет подготовка; алгоритм не получает «полувалидный» DTO.

## Команды

| Контракт | Достаточный вход после подготовки | Владелец и эффект | Предусмотренный исход |
| --- | --- | --- | --- |
| HireSpecialist | CommandId, StationId, OfferId/Revision, разрешённый actor context | Staffing; списание стоимости и создание контракта один раз | Accepted(HireId), AlreadyProcessed(result), Rejected(reason) |
| AssignStorage | BotId/группа, StorageId/Generation, filter, priority, expected binding revision | Logistics; новая редакция невидимой связи | Bound(revision), StaleBinding, UnsupportedStorage, NoPermission |
| EnqueueTask | Подготовленная цель, capability, scope, priority, ограничения | Scheduler; новая задача или ссылка на существующую по dedup key | Queued(TaskId), Existing(TaskId), Rejected(reason) |
| CancelTask | TaskId, ожидаемая редакция, право отмены | Scheduler; запрет новых микрошагов, затем освобождение резервов | CancelRequested, AlreadyFinished, NoPermission |
| ReserveTransfer | Source/Destination IDs, item kind, количество, версия снимка, TaskId | Logistics; резерв материала и подходящего места | LeaseGranted(actual amount), Unavailable(reason) |
| TransferStep | Подготовленные handles обоих инвентарей, LeaseId, количество, OperationId | World adapter; перенос фактически принятого количества | Applied(actual amount), Partial(actual amount, reason), Failed(reason) |
| RequestRoute | Начало/цель, граф/версия, capabilities, hazards, зоны запрета | Navigation; путь или доказуемый штатный отказ | Route(path,revision), NoRoute(reason), BudgetExhausted |
| PublishAnalysis | TaskId, исходная версия графа, user constraints revision, снимок фактов | Analysis; новый черновик редакции плана | Draft(plan revision), StaleSnapshot, Cancelled |
| ApprovePlanPart | PlanId/Revision, набор операций и замкнутые зависимости, роль пользователя | Plan service; закреплённая одобренная часть | Approved(operation set), StalePlan, IncompleteDependencyClosure |
| EditPlanConstraints | PlanId/Revision, зафиксированные/запрещённые узлы/рёбра, anchors | Plan service; новая редакция ограничений и задача анализа | ReanalysisQueued, Conflict(details), StalePlan |
| ApplyBuildStep | OperationId, принятая редакция, recipe/unlock, место, материалы, lease | World adapter; одна стройка по актуальным правилам игры | Built(EntityId), Blocked(reason), Failed(reason) |
| ApplyDismantleStep | OperationId, принятая редакция, EntityId/Generation, текущая подпись объекта | World adapter; один разрешённый снос и учёт возврата | Dismantled(actual refund), ChangedObject, Protected, Blocked |
| ConsumeHealing | BotId/Generation, предмет, ожидаемый живой получатель, OperationId | World adapter; штатное лечение и расход фактически использованного предмета | Applied, NoLongerNeeded, RecipientDead, Unsupported |

Названия исходов задают доменную семантику. Они не утверждают наличие аналогичного enum или метода в игре. `NoRoute` или пустой список допустимых работ — нормальный результат соответствующего алгоритма; отсутствие обязательного склада у подготовленной операции передачи — ошибка подготовки.

## Снимки и события

Снимок фактов — неизменяемые данные с version, coverage и observedAt. Он явно различает «область не обследована», «объект временно не загружен», «объект уничтожен» и «объект не поддерживается». Отсутствие в частичном снимке не означает уничтожение. UI показывает возраст и неполноту данных.

События `ObjectAdded`, `ObjectChanged`, `ObjectDestroyed`, `InventoryChanged`, `RouteInvalidated`, `BotDied`, `TaskProgressed`, `PlanRevisionPublished` содержат последовательный номер и ограниченный предметный payload. Обработчик обновляет собственную область. Потеря или переполнение событий обнаруживается номером последовательности и запускает ограниченное повторное чтение; события не являются единственным вечным хранилищем истины.

## Граница конкурентного изменения

Предварительная проверка права и снимка не резервирует мир. Перед применением микрошаг вновь получает подготовленное разрешение от владельца изменяемого состояния: объект жив, поколение то же, план актуален, материал доступен, место подходит и lease принадлежит задаче. Эти проверки выполняются рядом с изменением на game thread; внутренняя формула расчёта не повторяет их.

Lease содержит поколение выдачи (`fence`) и ID текущего исполнителя. Каждый физический эффект принимает только актуальные LeaseId/fence/attempt; после истечения, отмены или повторного назначения старый worker не получает право применить запоздалый результат. Перед выдачей остатка другому боту согласуются уже выполненные эффекты и физический груз прежнего исполнителя. Само истечение lease не означает, что изъятые предметы вернулись в источник или задача может безопасно начаться с нуля.

Резерв предметов — логическая договорённость между ботами. Игрок и фабрика могут изменить реальный инвентарь независимо. Поэтому `reserved <= observed` не гарантирует наличие предметов в момент изъятия. Исполнитель учитывает фактически изъятое/принятое число, уменьшает остаток задачи и освобождает неиспользованный резерв. Неуспех не превращается в успешную доставку нулевого количества.

Несколько игровых инвентарей не объявляются общей ACID-транзакцией. Операция использует маленькие сериализованные микрошаги и компенсируемое промежуточное владение в реальном рюкзаке/escrow. Удаление источника после изъятия не уничтожает уже перенесённый груз; удаление назначения требует нового назначения для имеющегося груза, а не повторного изъятия.

## Адаптеры возможностей

| Вид объекта | Сначала поддержать | Что проверить отдельно |
| --- | --- | --- |
| Ванильный контейнер | Чтение слотов, допустимость предмета, частичное изъятие/внесение | Полный/удалённый/выгруженный контейнер, открытый инвентарь игрока |
| Конвейер, лифт, splitter/merger | Направленный граф портов и пропускная способность | Tier, фильтры, приоритеты, частичная насыщенность, нестандартная модовая логика |
| Труба, junction, насос, клапан | Жидкостные связи и тип среды | Напор, высота, буфер, направление/лимит клапана; не сводить к обычному конвейеру |
| Электросеть, аккумулятор, генератор | Связность, производство/потребление и наблюдаемые пики | Приоритеты отключения, fuel/water dependencies, перегрузка и накопленная энергия |
| Производство | Рецепт, unlock, вход/выход, мощность, рабочий режим | Разгон, альтернативные рецепты, жидкие входы, пользовательская конфигурация |
| Станции машин/поездов/дронов | Наблюдение маршрутов, расписаний, буферов и топлива | Сигнализация, стыковка, питание, права на редактирование расписаний |
| Ресурс, живность, растительность | Наблюдение разрешённой цели, безопасное штатное действие | Истощение, respawn, уникальные предметы, защитные зоны, отсутствие достижимости |
| Blueprint/чертёж | Проверенный собственный шаблон и список операций | Пользовательский blueprint, его лимиты, ссылки и реальные требования игры |
| Чужой модовый объект | Идентификация и безопасное чтение поддержанных интерфейсов | Запись только через проверенный адаптер и явный capability |

Порт конвейера и пеший маршрут имеют разные семантику и граф; наличие конвейера между складами не доказывает, что бот может пройти между ними. Связь хранения логическая и невидима в мире; визуальные линии появляются только в режиме настройки и на планшете.

## Неизвестные объекты и версии

Неизвестный модовый рецепт, ресурс, транспорт, враг или хранилище получает статус `Unsupported(reason)`, остаётся видимым в диагностике и не блокирует очередь навсегда. Отдельный адаптер добавляется после проверки. Нельзя изменять чужие классы глобальным перехватом только ради того, чтобы «работало со всеми модами».

При несовпадении protocol/schema version UI получает явный режим read-only или отказ подключения. Миграция сохранения и сетевое согласование — разные контракты. Результат команды хранится ограниченное время в контексте сессии; необратимые подтверждённые операции идентифицируются также по сохраняемому OperationId/HireId, чтобы повтор после reload не создавал дубль.
